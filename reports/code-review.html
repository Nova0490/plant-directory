Код-ревью: шторка и форма

Проект «Домашний гербарий» · 2026-10-18 · ревью по состоянию кода на момент проверки (файлы не менялись)
Общий вердикт: уровень — уверенный junior (Junior+/Junior Middle). Код читаемый, типизированный, структура компонентов аккуратная, строгий TypeScript и линт проходят чисто. До миддла не хватает: реализации ключевой бизнес-логики (выгрузка данных), валидации, доступности (a11y), единого состояния и тестов. Технические навыки для миддла — на месте; не хватает «доделанности» и системности.

1. Что в проекте и как устроено

Vite + React 19 + TypeScript (strict) + react-router. Хранилище — localStorage через модуль src/storage.ts (уже написаны loadPlants, savePlants, generateId, тип-гард isPlant). Форма «Добавить растение» открывается в шторке (drawer), которая живёт в AddPlantButton.

Поток данных сейчас

Красным — разрыв цикла данных: форма не сохраняет, коллекция не читает из хранилища.

3. Ревью формы (NewPlantForm)

Что хорошо

  • [+1] Один handleChange на все поля — компактно; конвертация interval в Number и дат в timestamp на месте.
  • [+1] Reset работает через setFormData(createInitialForm()) — правильное осознание управляемых инпутов.
  • [+1] Счётчик символов {formData.note.length}/240, лимиты maxLength — внимание к UX.
  • [+1] Пустые <p id="nameMsg" ...> — задел под сообщения валидации (пока статичные).

Критическое: выгрузки данных нет

handleSubmit только делает console.log('submit', formData). Форма не сохраняет растение, карточки в коллекции захардкожены. storage.ts уже готов — нужно всего лишь:

function handleSubmit(e: FormEvent) {
  e.preventDefault();
  const plant: Plant = {
    id: generateId(),
    name: formData.name.trim(),
    room: formData.room,
    interval: formData.interval,
    lastWatered: formData.lastWatered,
    note: formData.note.trim() || undefined,
  };
  savePlants([...loadPlants(), plant]);
  onSaved(plant);  // чтобы родитель обновил коллекцию
  handleReset();
}

Это 6–8 строк. Дальше — поднять состояние коллекции на уровень выше (например, в Desktop), чтобы и форма писала, и секции читали один источник правды.

Проблемы валидации (реальные баги)

СерьёзностьГдеЧто не такКак исправить
HIGHlastWateredПустой date-input даёт new Date('').getTime() = NaN. При require браузер блокирует пустой submit, но при «вчера заполнил, сегодня открыл» поле само пустое при открытии — и валидация браузера сработает с кирпичом. Хуже: после NaN — new Date(NaN) вернёт Invalid Date и поле «залипнет».В handleChange обрабатывать пустую строку: value ? new Date(value).getTime() : Date.now(); или хранить дату строкой, конвертировать только при submit.
HIGHintervalNumber(value) — пустая строка → 0, а min={0} разрешает 0. Отрицательные и дробные числа type="number" пропускает (браузер валидирует только при step), и ничего в handleChange это не режет.В handleChange для interval: Number.isInteger(v) && v >= 0 && v <= 90, иначе — не обновлять / показать сообщение.
MEDdatenew Date(...).toISOString().split('T')[0] — срез по UTC. У пользователя в +03:00 «сегодня» может показать вчерашнюю дату в инпуте.Форматировать локально: toLocaleDateString('en-CA') (даёт YYYY-MM-DD в локальном времени) или вручную из getFullYear/getMonth/getDate.
MEDnameПодсказка «После trim, обязательное» — а trim в коде не делается, имя с пробелами сохранится как есть; при submit пустая строка из пробелов пройдёт (браузерный required проверяет непустоту, а не отсутствие пробелов).Валидировать name.trim() при submit.
LOWвсе msg-текстыПодсказки статичны и видны всегда, даже когда поле валидно. Лучше показывать ошибку только после касания (touched) — это ожидание пользователей.Состояние touched на поле или библиотека форм (react-hook-form / Formik).

Замечания по коду формы

  • LOW handleChange — тройной тернарник в setFormData трудно читать; лучше вынести в switch или мапу конвертеров.
  • LOW aria-required="true" дублируется с required — достаточно одного; с required и :user-invalid CSS можно показывать ошибки без JS.
  • LOW collection и lastWateredDate рассчитаны в render — ок, но при большей форме лучше useMemo.

4. Среды: типы и хранилище

  • [+] storage.ts — пример хорошего кода: тип-гард isPlant, обработка ошибок JSON, дефолт [], generateId с фолбэком. Это уже миддловский уровень.
  • [+] Неточность: savePlants в catch пишет «Failed to load plants» вместо «Failed to save» — мелочь, но внимательность к текстам — маркер.
  • MED VALID_ROOMS в storage.ts и ROOMS в форме — один и тот же список в двух местах. Если добавишь комнату, сломается один из них. Вынести в один модуль (например, в types.ts или константы).
  • MED Состояние коллекции нигде не поднято: CollectionSection рендерит 5 копий одной карточки вручную, TodayCareSection — заглушка «3 растения», цифры «07», «27 Aug» — хардкод в Copy.tsx. Всё это должно считаться из единого состояния.
  • MED CollectionCard.tsx содержит мусорный текст «йцуккеекнкевфы» в статусе и компонент принимает Plant целиком, хотя интервал/дата должны форматироваться, а кнопки «Полито/Редактировать/Удалить» — без логики. Пока это витрина, не данные.

6. Дорожная карта до миддла (по шагам, в порядке важности)

Шаг 1. Замкнуть цикл данных (1–2 часа)

  1. Поднять коллекцию в состояние Desktop (или App): const [plants, setPlants] = useState<Plant[]>(loadPlants).
  2. Прокинуть onSave в форму; при submit — savePlants + обновление состояния.
  3. CollectionSection и TodayCareSection рендерить из plants, считая «сегодня поливать» по lastWatered + interval*86400000.
  4. Карточку удалить; кнопку «Полито сегодня» — обновлять lastWatered.
// Desktop.tsx (схема)
const [plants, setPlants] = useState<Plant[]>(loadPlants);
const addPlant = (plant: Plant) => {
  const next = [...plants, plant];
  setPlants(next);
  savePlants(next);
};
// <NewPlantForm onSave={addPlant} />
// <CollectionSection plants={plants} />

Шаг 2. Валидация (2–3 часа)

  1. Показывать ошибки после touched; проверять name.trim(), interval целое 0–90, дату — не в будущем.
  2. Обрабатывать пустой date (NaN) — хранить строку до submit.
  3. Локальные даты вместо toISOString.

Шаг 3. Доступность шторки (1–2 часа)

  1. Focus trap + возврат фокуса на кнопку; inert на закрытой шторке.
  2. Убрать дубли aria-required/required, подключить :user-invalid.

Шаг 4. Проектные практики (непрерывно)

  1. Преттиер/ESLint, единые импорты; убрать мёртвый код (toggle, хардкод-цифры).
  2. Разнести дублирующиеся списки комнат в один модуль.
  3. Тесты на storage.ts (Vitest + Testing Library): добавление, загрузка битых данных, фильтр тип-гарда.
  4. Покрыть тестом валидацию формы и цикл «отправил → появилась карточка».
  5. git-инициация проекта и коммиты по шагам — чтобы видеть историю и откатываться.

Шаг 5. Чтобы выглядеть как middle на собеседовании

  • Уметь объяснить, почему type="reset" не работает на controlled-форме (ты уже знаешь).
  • Уметь объяснить, почему toISOString().split('T')[0] — баг с таймзоной.
  • Уметь объяснить разницу uncontrolled/controlled, когда нужен useMemo/useCallback.
  • Знать React Context vs props drilling vs state-менеджер (для этого проекта Context достаточно).
  • Знать, что такое focus trap, почему aria-modal без него — ложь для скринридеров.
